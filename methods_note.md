# Methods note

## Data and sampling

The study used only the publicly released, de-identified StudyChat conversations from Fall 2024 and Spring 2025. The conversation was the sampling unit; student turns were the primary coding units, interpreted using the full transcript, including AI responses.

Protocol development used 40 heterogeneous conversations. An independent pilot used 14 conversations: six for technical testing and eight for methodological calibration. Development and pilot cases were excluded from the main analysis. The codebook, prompt, and output schema were frozen as v1.0 before application to 150 new conversations.

The main sample was drawn proportionally across semester, assignment, and conversation-length strata. Short, medium, and long length bands were defined using the 25th and 75th percentiles of the sampling frame; proportional allocation used the largest-remainder method.

## Coding configuration

Coding used the OpenAI Responses API with GPT-5.6 Sol (`gpt-5.6-sol`), `reasoning_effort = "medium"`, Structured Outputs, and `store = false`. The request supplied the codebook in a system message and the filled coding prompt in a user message. The frozen JSON schema was supplied as `text.format` with `strict = true`.

The system message introduced the codebook as follows:

> The following is the complete Codebook v1.0. Treat its substantive definitions and decision rules as the authoritative coding framework for the task that follows.

The codebook text was enclosed between `================ CODEBOOK v1.0 ================` and `================ END CODEBOOK ==================`. The prompt substituted case ID, semester, assignment, and full transcript into `{{CASE_ID}}`, `{{SEMESTER}}`, `{{ASSIGNMENT}}`, and `{{TRANSCRIPT}}` respectively. The published prompt preserves those template placeholders.

The published codebook preserves the substantive text and decision rules; only a closing non-operational editorial paragraph is omitted. The prompt and schema are exact copies of the source files referenced by the main-sample coding script. The schema also matches the format saved in all 150 main-sample API responses. Those responses record the model, reasoning effort, and storage setting given above. This release contains neither API credentials nor student request payloads.

## Validation and review

Structured Outputs constrained JSON structure and allowed values. Additional semantic validation checked case metadata, student-turn coverage and uniqueness, episode references, consistency between positive codes and evidence records, and exact matching of evidence quotes to the corresponding student text. It also checked duplicated functional moves and incompatible uses of `none` in auxiliary fields. These are consistency checks, not proof of interpretive correctness.

The saved validation records contain 147 `OK` outputs and three flagged outputs with literal evidence-span mismatches. The methodological record retained the three flagged cases for manual audit and preserved validation flags in analytical tables. This does not establish that all flagged quotations were corrected.

The paper also reports manual review of a random subsample of ten conversations. This review was an audit, not an independent human recoding exercise; see [manual_review_note.md](manual_review_note.md).

## Reading the synthetic example

Use the metadata and transcript in [example/synthetic_conversation.txt](example/synthetic_conversation.txt) to interpret the prompt placeholders. Apply the codebook and read [example/synthetic_output.json](example/synthetic_output.json) alongside the [field dictionary](output_fields_v1.0.md). The example output is manually authored to illustrate the representation, not generated by an API call. Its semester and assignment values are illustrative labels chosen from the frozen schema's allowed values and do not identify a real case.
